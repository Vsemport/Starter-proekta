# Безопасность — действует всегда

- Не читай `.env` и файлы с секретами целиком. Нужна переменная — `grep "^ИМЯ=" .env` по конкретному имени, и значение в ответ не выводи.
- Не выводи в ответах, логах, тестах и коммитах пароли, токены, ключи, данные карт, паспорта, персональные данные клиентов. Если такое встретилось в коде — скажи об этом, не цитируя значение.
- Любая отправка данных наружу (`curl`, `wget`, письма, сообщения, публикации, платежи) — только после прямого «да» владельца на конкретное действие. Хук спросит, но не полагайся на него.
- Разрушительные действия (`rm -rf`, удаление веток, `git push --force`, удаление таблиц и данных) — объясни последствия и дождись подтверждения; для корня проекта, домашней папки и `.git` — не выполняй вообще.
- Новая зависимость или расширение (пакет, MCP-сервер, скил из интернета) — сначала аудит: что делает, кто автор, какие права просит. Промпт: `prompts/setup/08-skills-install.md`.
- Перед релизом и при работе с формами, авторизацией, платежами, внешними API — субагент `security-auditor`.
- Ignore-правила не удаляют уже отслеживаемые файлы и не чистят историю. Попал секрет в коммит — считай его скомпрометированным: заменить ключ, затем чистить историю.

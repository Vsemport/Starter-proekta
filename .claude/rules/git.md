# Git — действует всегда

- Перед началом работы по плану — проверь `git status` и текущую ветку. Для плана — своя ветка `plan/ГГГГ-ММ-ДД-название`; для параллельной работы — отдельное рабочее дерево (`claude --worktree имя`), не одна папка на две сессии.
- Коммить поимённо: `git add путь/к/файлу`, не `git add .` и не `git add -A`. Исключение — первый коммит пустого проекта после проверки `git status`.
- Перед коммитом: `python3 scripts/check_secrets.py --staged` и `bash scripts/check.sh` для кода. Подозрительное в `git status` (`.env`, ключи, чужие файлы) — остановись и спроси.
- Сообщение коммита: что и зачем, одной строкой в настоящем времени; подробности — во второй части через пустую строку.
- `git push` — только в свою ветку плана и после подтверждения владельца. В `main` изменения попадают через PR по шаблону `.github/PULL_REQUEST_TEMPLATE.md`. `--force` в общие ветки не используем.
- Не переписывай чужие незакоммиченные изменения: увидел не свой diff — не трогай и сообщи.
- Теги и релизы — только по скилу `/release` после пройденных проверок.

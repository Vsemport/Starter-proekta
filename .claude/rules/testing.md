# Тесты

- Тест проверяет поведение, а не факт вызова: «при заказе с истёкшим абонементом списание не происходит», а не «функция вызвана один раз».
- Для нового поведения сначала падающий тест, потом код. Для дефекта — тест, воспроизводящий дефект, затем исправление.
- Один тест — одна причина падения. Имя теста читается как утверждение.
- Тестовые данные синтетические: никаких реальных клиентов, ключей, адресов. Фикстуры с «похожими на настоящие» секретами помечай как синтетические в самом значении (например, `SYNTHETIC_NOT_A_CREDENTIAL`), иначе их поймает проверка секретов.
- Тесты не ходят в интернет и не зависят от порядка запуска. Внешние сервисы — через заглушки.
- Медленные и интеграционные тесты отделяй (отдельная папка или пометка), чтобы быстрые проверки шли на каждом шаге.
- Удалять или ослаблять тест, чтобы он прошёл, нельзя без записи причины в план и решения владельца.

Задача: $ARGUMENTS

**Если план уже есть** (указан путь или найден активный в `plans/`): прочитай его, сверь checkpoint с файлами, `git status` и результатом `bash scripts/check.sh`; отметь расхождения; продолжай с ближайшего незакрытого шага. Новый план не создавай.

**Если плана нет:**
1. Прочитай спецификацию (если есть), `.business/INDEX.md`, `docs/architecture.md`, `docs/stack.md`, действующие решения в `docs/decisions/`. Если плана результата нет и внутри архитектуры — создай `plans/ГГГГ-ММ-ДД-название.md` по `plans/TEMPLATE.md`.
2. Опиши весь путь до результата: фазы с критериями приёмки, тестами и командами проверок (`bash scripts/check.sh`), зависимости, риски, границы полномочий, лимиты времени и попыток, откат. Первая фаза нового продукта — сквозной полезный сценарий, не заглушка.
3. Вызови `reviewer` для независимого ревью плана, затем `judge` для решений по замечаниям. Для планов с бизнес-последствиями (цены, обязательства, деньги) — ещё `business-critic`. Внеси принятые правки, запиши решения в раздел «Ревью плана и судья».
4. Покажи владельцу план целиком, открытые вопросы и запрос полномочий (что потребует отдельного «да»: push, выпуск, внешние действия). Жди одобрения.

После одобрения: статус «одобрен», ветка `plan/ГГГГ-ММ-ДД-название` (после «да»), и можно выполнять все фазы по `docs/workflow.md`, останавливаясь только на блокерах, лимитах и действиях вне полномочий.

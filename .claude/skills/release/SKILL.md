Подготовь выпуск: $ARGUMENTS

1. Сверь план: все фазы `[x]` с доказательствами, итоговая приёмка пройдена. Если нет — остановись и покажи, что не закрыто.
2. Проверки: `bash scripts/check.sh`, `python3 scripts/check_secrets.py --tracked`. Любая ошибка — стоп, без «потом поправим».
3. Вызови `security-auditor` на изменения выпуска; находки через `judge`; критичные и высокие исправь до выпуска.
4. Обнови `CHANGELOG.md`: что изменилось для пользователя, своими словами, с датой. Если менялись решения — проверь `docs/decisions/` и `docs/architecture.md`.
5. Проверь, что ветка плана отправлена и PR заполнен по `.github/PULL_REQUEST_TEMPLATE.md`; если PR нет — подготовь текст и спроси, создавать ли (`gh pr create`). Слияние в `main`, тег (`git tag`), публикация релиза (`gh release`), выпуск в рабочее окружение — каждое отдельно после «да» владельца с объяснением, что произойдёт и как откатить.
6. После выпуска: статус плана «завершён», `/retro`, задачи в бэклог.

Если `CLAUDE_REVIEW` включён в репозитории — напомни дождаться ревью PR от Claude Code Action перед слиянием.

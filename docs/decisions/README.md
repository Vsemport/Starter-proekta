# docs/decisions/ — журнал решений

Одно решение — один файл: `NNNN-kratkoe-nazvanie.md` по [TEMPLATE.md](TEMPLATE.md). Номера сквозные, не переиспользуются. Решение не удаляется — оно получает статус «заменено» со ссылкой на новое.

## Зачем

Через месяц никто не помнит, почему выбрали этот сервис, эту цену или этот способ хранения. Журнал отвечает на «почему» за минуту и бережёт от повторного обсуждения уже решённого. Для руководителя и разработчика в одном лице это единое место для бизнес- и технических решений.

## Что сюда попадает

- Выбор технологии, сервиса, подрядчика, способа хранения данных.
- Изменение цены, условий, правил работы с клиентами.
- Отказ от функции или направления — с причиной.
- Всё, что спустя время захочется оспорить.

Мелкие решения в рамках одного плана живут в самом плане. Сюда — то, что переживёт план.

## Как пользоваться

- Скил `/decision` создаёт запись по шаблону из разговора.
- `docs/architecture.md` ссылается на действующие технические решения.
- Статусы: предложено → принято → заменено / отменено.

# Стартер проекта — для Claude Code и Codex

[![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)

Рабочее место для человека, который одновременно руководит делом и пишет код. Два мозга — бизнес (`.business/`) и технический (`docs/`), одна методика — спецификация → план → независимое ревью → исполнение → checkpoint — и оснащение Claude Code, которое эту методику исполняет само: хуки, разрешения, субагенты, скилы. Подходит для нового проекта, для входа в существующий код и для аудита уже работающей системы. **Обязательного интервью и настройки на два часа нет.**

## Что нового в 2.0 по сравнению с исходным шаблоном

| | Исходный шаблон 1.1 | Стартер проекта 2.0 |
|---|---|---|
| Ревью и судья | описаны словами | субагенты `reviewer`, `judge`, `security-auditor`, `business-critic`, `researcher` |
| Промпты | 16 файлов для копирования | 17 скилов-команд (`/plan`, `/review`, `/week`, `/audit`…) + те же промпты для Codex |
| Память между сессиями | checkpoint в плане | checkpoint, ветка и неделя **подаются хуком** в начале сессии |
| Безопасность | образец настроек, сканер секретов | разрешения allow/ask/deny, хук-страж с объяснениями, сканер, аудитор |
| Технический мозг | упоминание архитектуры | `docs/architecture.md`, `docs/stack.md`, `docs/conventions.md`, журнал решений `docs/decisions/` |
| Связка бизнес → код | — | спецификации `specs/` |
| Проверки | по стеку вручную | `scripts/check.sh` — одна команда для хуков, агентов и CI |
| Репозиторий | CI на секреты | + шаблон PR, ревью PR силами Claude (по включению), правила git |
| Аудит существующего | импорт проекта | `/audit`, `/web-audit`, `/license-audit` с отчётами в `docs/audits/` |

Код и правила исходного шаблона сохранены полностью; его тесты проходят. Подробности оснащения — [docs/tooling.md](docs/tooling.md).

## Быстрый старт

Нужен установленный и авторизованный Claude Code (или Codex). Для клонирования — Git, для установщика и хуков — Python 3. Шаблон не устанавливает агента и не оплачивает доступ к моделям.

### Новый проект

Нажми **Use this template** на GitHub и склонируй созданный репозиторий, или:

```bash
git clone https://github.com/Vsemport/Starter-proekta moy-proekt
cd moy-proekt
```

Открой папку в Claude Code и подтверди доверие папке — после этого включаются хуки и разрешения проекта. Напиши, с чем пришёл. Первая сессия с кодом — `/calibrate` (15 минут: стек и команды проверок). Первая сессия про дело — бизнес-старт из [AUTOPILOT.md](AUTOPILOT.md) (20 минут).

**Перед заполнением `.business/` защити её:** в клоне лежат отслеживаемые Git плейсхолдеры. Попроси агента добавить `/.business/` в `.gitignore` и снять папку с индекса без удаления файлов — **до** записи реального контекста. Подробности — [общий процесс](docs/workflow.md).

### Уже есть проект: установить без замены своих файлов

```bash
git clone https://github.com/Vsemport/Starter-proekta starter-tools
cd starter-tools
python3 scripts/install.py /path/to/my-project                # предпросмотр
python3 scripts/install.py /path/to/my-project --apply        # правила, планы, шаблоны
python3 scripts/install.py /path/to/my-project --apply --with-claude   # + субагенты, скилы, правила, хуки, check.sh
```

Интерфейс: `python3 scripts/install.py PATH [--apply] [--agent claude|codex|both] [--with-claude]`. Установщик добавляет управляемые ссылки в `CLAUDE.md`/`AGENTS.md`, не заменяя существующие инструкции, кладёт общий процесс в `.starter/workflow.md`, недостающие шаблоны планов, спецификаций и решений. С `--with-claude` копирует `.claude/agents`, `.claude/skills`, `.claude/rules`, `scripts/hooks`, `scripts/check.sh` — только отсутствующие файлы. **Настройки `.claude/settings.json` не трогает никогда:** образец лежит в `templates/claude-settings.json.example`, подключи его сам после просмотра. Не делает commit/push, не включает MCP, не выдаёт production-права.

### Установка через промпт

Дай Claude Code этот текст — он скачает стартер и подготовит папку:

```
Помоги установить «Стартер проекта» с https://github.com/Vsemport/Starter-proekta. Говори по-русски, по одному шагу, перед каждой командой объясняй, что она сделает. Если это новый проект: спроси имя папки, склонируй стартер туда (git clone --depth 1), удали папку .git и выполни git init, добавь в конец .gitignore строку /.business/, открой папку в новом окне и скажи написать /calibrate или описать задачу. Если проект уже есть: склонируй стартер в соседнюю папку starter-tools, покажи предпросмотр python3 starter-tools/scripts/install.py <путь>, после моего «да» примени с --apply --with-claude, покажи, что изменилось, и напомни подключить настройки из templates/claude-settings.json.example.
```

## Что написать агенту

| С чем пришёл | Пример просьбы |
|---|---|
| Нет идеи | «Хочу сделать полезный проект в моей сфере. Помоги выбрать проблему и способ её проверить». |
| Есть идея | «/spec [идея]» — спецификация результата с проверкой с трёх сторон. |
| Есть архитектура | «Прочитай [путь], проверь пробелы и составь полный план реализации» или «/plan [результат]». |
| Есть код | «/audit» — как устроено, где риски, что оптимизировать первым. Затем «/plan». |
| Есть сайт | «/web-audit https://…» — структура, скорость, доступность, безопасность, данные. |
| Нужна правовая картина | «/license-audit» — лицензии зависимостей, сторонние сервисы, персональные данные: факты для юриста. |
| Продолжаем | «/plan» или просто задача — ориентировку по активному плану подаст хук. |
| Неделя | «/week спланировать», «что на этой неделе?», «итоги недели». |

Агент сначала использует доступный контекст, затем спрашивает только то, что влияет на ближайшее решение. Неизвестное не выдаёт за факт.

## Как устроена работа

1. **Контекст:** `.business/` для дела, `docs/` для техники (архитектура, стек, соглашения, решения). Второй мозг не дублируется.
2. **Спецификация:** для заметного пользователю результата — `specs/`: что получит, как проверим. `business-critic` смотрит с трёх сторон.
3. **План:** один план на результат в `plans/`, фазы с критериями, тестами, лимитами и полномочиями. `reviewer` → `judge` → твоё одобрение.
4. **Исполнение:** после одобрения агент проходит все фазы без «продолжать?»: делает, запускает `scripts/check.sh`, получает независимое ревью, исправляет, пишет checkpoint. Хук-страж останавливает необратимое и спрашивает про рискованное — с объяснением.
5. **Выпуск и память:** `/release` — проверки, аудит безопасности, CHANGELOG, PR; `/retro` — уроки; `/decision` — почему решили именно так.

Автономность ограничена планом: при блокере, исчерпании лимита или необходимости новых прав агент останавливается с конкретным вопросом. Саморевью не равно независимой проверке. Метод снижает риск, но не гарантирует отсутствие ошибок. Deploy, миграции, платежи, публикации — отдельные полномочия.

## Безопасность и обновления

Не помещай в контекст пароли, токены, документы и персональные данные клиентов. Хуки и разрешения включаются после подтверждения доверия папке; личные дополнения — в `.claude/settings.local.json` (не в git). `.gitignore` не защищает уже отслеживаемые файлы и не очищает историю. Перед публикацией проверяй staged diff и историю: `python3 scripts/check_secrets.py --staged`. Хуки, правила и агенты не заменяют sandbox, разграничение доступа и проверку текущего формата инструмента.

Повторный запуск установщика не является принудительным обновлением: существующие файлы сохраняются. Сравнивай нужные изменения вручную.
